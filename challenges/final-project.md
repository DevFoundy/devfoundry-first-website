# Final project

Your final task is to personalize and explain the website independently. You may refer to this workbook and the complete solution, but make meaningful decisions about content, design and behavior. The goal is a site you can understand and maintain, not a screenshot you copied without understanding.

### Required content and features

- Navigation that reaches all major sections, with a usable mobile menu.
- Hero with your name, focus and a clear next action.
- About section and a genuine skills list.
- At least three project cards with titles, descriptions and images or meaningful visual alternatives. Clearly identify unfinished concepts.
- Contact section with a working public contact method, plus a footer.
- Responsive layout from approximately 320px through desktop, with no horizontal page overflow.
- Consistent CSS styling, readable contrast, visible keyboard focus, and hover or transition feedback with reduced-motion support.
- Working dark/light toggle and project filters, alongside the mobile-menu interaction from Project 4.
- Git repository, useful README, meaningful commits, public deployment and one verified live update.

### Personalization brief

Replace all example identity details and metadata. Write your own introduction and project descriptions. Change at least two visual choices, such as the accent palette and card styling, while preserving readability. Add at least one real project destination when you have work available; do not use # links to imply an external project exists. Explain your three interactions in a short README section.

### Suggested independent build sequence

Sketch the sections on paper. Write your content before choosing colors. Rebuild or review the HTML landmarks. Apply the shared design tokens, then layout. Test the narrow viewport before adding more motion. Implement one interaction at a time and test it. Review your repository, deploy, and check the live URL in a fresh browser tab.

### Bonus challenges

Save the theme preference if you have only implemented the minimum toggle. Add a custom favicon. Build another actual project and replace a planned concept. Add a gentle scroll animation with reduced-motion support. Extend the project filters with another category and a zero-result message. Connect a custom domain later.

A contact form is an advanced extension: static HTML alone does not deliver messages. Use a service or backend, provide labels and status feedback, and avoid claiming submission succeeded until the service confirms it. Do not place private service credentials in frontend JavaScript.

## Final project assessment

Use this rubric to assess work consistently. Score each area from 0 to 4: 0 absent, 1 substantially incomplete, 2 works with important gaps, 3 meets the requirement, 4 meets it and you can explain your choices and testing. This is a self-assessment tool, not an accredited certification.

| Area | Evidence for a score of 3 |
| --- | --- |
| Content and HTML | Required sections, honest project descriptions, meaningful headings and unique IDs |
| CSS and visual clarity | Reusable styling, readable text, consistent cards, no distorted images |
| Responsive behavior | 320px, 390px, 768px and 1440px checks pass without horizontal overflow |
| JavaScript and usability | Theme, menu and filters work; keyboard and no-script fallbacks checked |
| Repository and delivery | README, meaningful commits, live URL and verified update recorded |

Target: at least 15 out of 20, with every required item complete. A high total does not override a broken deployment or inaccessible navigation. Fix missing essentials and rerun the checks.
