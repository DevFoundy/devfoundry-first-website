# Licensing proposal — not approved

The owner requested that files be prepared while licensing remains pending. Neither proposal below is an effective license grant.

## Recommended split

- **MIT** for executable example source: checkpoint HTML, CSS and JavaScript, plus code snippets reproduced in the workbook and documentation.
- **CC BY 4.0** for the workbook's explanatory prose, Markdown teaching material and original illustrations, diagrams and screenshots, excluding the code snippets governed by MIT.

Checkpoint `assets/*.svg` illustrations would follow the educational-visual license rather than the source-code license. Any separately identified third-party material would keep its own terms. This explicit split avoids accidentally treating every file under a code folder as software.

Both licenses allow commercial reuse. MIT requires preserving its copyright and permission notice in copies or substantial portions. CC BY 4.0 requires appropriate credit, a license link and an indication of changes, without suggesting endorsement. CC BY freedoms cannot be revoked from compliant recipients after the license is granted. Neither proposal is a grant of trademark rights to the DevFoundry name or logo.

CC BY-SA 4.0 is an alternative if the owner wants shared adaptations to use the same license. It adds share-alike obligations. A noncommercial-only restriction would not fit the usual meaning of open-source licensing for code, and is not this proposal.
